# KLIO garbage collector — design & staged implementation plan

Replaces manual reference counting with a tracing mark-sweep GC: objects are freed by
**reachability**, so missing-retain/over-release become harmless and cycles are collected.
This is the general, correct-for-any-program answer; the ~19 audited per-site ownership
fixes keep the interim refcount path correct but the tail is unbounded by hand.


## Chosen approach

PRECISE tracing mark-sweep at opcode-boundary safe points, with the conservative native-stack scan demoted to a debug-only ORACLE rather than the production root mechanism. Concretely: graft Design 4's "reuse Value.retain's structural walk as the tracer + reuse T.deinit (split shallow) as the finalizer + neutralize refcount to no-op" onto Design 2/3's explicit, closed root registry (active-frame chain per thread, parked SuspendStates, scheduler/coroutine/cross-thread queues, Vm/program graph), plus Design 1's permanent generation for the immutable stdlib/ClassDef image, plus Design 1's conservative stack scan kept ONLY as a build-time differential oracle that asserts the precise root set is a superset of the conservatively-reachable set. Stage to a non-moving generational nursery (Designs 2/3/4 all agree) with a write barrier confined to the few heap-mutation sites. Address identity (===/ptrEq) forces non-moving at every stage.


## Final design

UNIFIED TRACING-GC DESIGN (final, after resolving the adversarial holes)

GC-managed unit = every `ControlBlock(T)` minted at the single chokepoint `ObjRef(T).initOwned` (src/runtime/objcell.zig:326). Every reference-typed `Value` variant (value.zig:263) bottoms out there: StringRef=`ObjRef([]const u8)`, ValueList/Array/Set items=`ObjRef(std.ArrayList(Value))`, MapEntries=`ObjRef(std.ArrayList(MapPair))`, ValueBox=`ObjRef(Value)`, ValueSlice=`ObjRef([]Value)`, `ObjRef(InstanceData)`, `ObjRef(Env)`, `ObjRef(ClassDef)` + companion/object_singleton/enclosing_class/captured_env/nested/parent, Comparator steps, Sequence/Regex/Match/StringBuilder/Cell/Iterator.pos/RangeIter.cur/Delegate/DriverWakeup. Plain scalars (Int..Char, Range, Null, Intrinsic.fqn/BoundMethod.fqn which borrow module consts) are immediate, never managed.

OBJECT MODEL. Add a `GcHeader` to `ControlBlock(T)` (objcell.zig:266): { mark_epoch: u32 (epoch-compare = "marked", no clear pass), gen: u8 (nursery/old/perm), next/prev: ?*GcHeader (intrusive per-generation all-cells list for sweep), trace_fn: *const fn(*anyopaque, *GcVisitor) void, finalize_fn: *const fn(*anyopaque) void — both comptime-specialized thunks filled by the `ObjRef(T)` body at `initOwned`, gen set from a threadlocal `gc_alloc_gen` (perm during stdlib/module load, nursery otherwise) }. The header and link pointers live in the control block, never in the by-value `Value` (Values are copied everywhere — regs/params/snapshots — a mark bit in the Value would be lost). Keep `refcount` (load-bearing for `strongCount`/identity at objcell.zig:450) and `SpinRwLock` (mediates genuine cross-thread mutation between safe points); neither is consulted for freeing.

EDGE DISCOVERY (single source of truth). Extract `Value.retain`'s per-variant switch (value.zig:458-505) into `Value.forEachChildCell(self, visitor)` — the one function `retain` (incref), `release` (decref), and the GC tracer (mark) all call, so they cannot diverge. Per-T `trace_fn` mirrors `forEachChildCell` of the payload: ArrayList(Value) iterates items; InstanceData walks class + fields[].value + outer + enum (class.zig:269-280); Env walks parent + vars values (env.zig:15-17); ValueBox/Cell pushes the boxed Value; leaf payloads (`[]const u8`, RegexData.engine, ArrayList(u8)) have no Value out-edges. ClassDef parent/interfaces/nested_classes[].class/companion/enclosing_class/object_singleton/enum_entries[].value/captured_env become trace edges so the class graph is a root-reachable subgraph (these cells are minted into perm, so they are implicitly live and not actually traced in steady state — see PERM GEN).

ROOTS (closed, enumerable, precise — the whole correctness argument).
(1) ACTIVE FRAMES, all threads. Add a threadlocal intrusive frame stack: push a node in `evalWithCapturesChained` next to `frame.activateChain` (eval.zig:701) and pop next to `defer frame.deinit` (eval.zig:699); same in the resume-path frames of `resumeContinuation` (eval.zig:772). Each thread registers its {frame-stack head, scratch-root vector, coro_stack head} in a process-global `GcThreadTable` on entry and deregisters on exit, reusing the exact spawn-seed inheritance plumbing that propagates reclaim mode (scheduler.zig:323 `setReclaim`, intrinsic_host.zig workerEntry, run.zig vmSpawnChild). Mark regs/params/captures items and enclosing_this[].v of every frame in every thread's chain. The `active_chain` threadlocal (eval.zig:187) points into the top frame's `enclosing_this` ArrayList, already covered by that frame's node. Also mark the in-flight `try_stack` exception Values (eval.zig:696, TryFrame) and `runFrameInner`'s local `thrown`/`resume_throw`/`pending_return`/`pending_rethrow` Values — these are live on the native stack between opcodes; the scratch-root rule (5) covers anything not in an ArrayList the frame node already reaches, but try_stack is reachable from the frame node so we add it to the node.
(2) PARKED COROUTINES. Walk every registered thread's coro_stack: each `CooperativeInterceptor`'s `parked` map entries (ParkedEntry.state.frames[].{regs,params,captures,enclosing_this} + scope_delta), `token_resume_value` map, `launched` list, plus the slot-resume-pending Values; plus process-global `PersistedParked.map` (Entry.state.frames + scope_delta, coroutines.zig:262) and `SlotOwners.pending` (coroutines.zig:181). Add `SuspendState.markRoots`/`FrameSnapshot.markRoots` that mirror `retainSnapshotValues` (eval.zig:405) EXACTLY — the proven-necessary retain set IS the root set; a unit test asserts the two enumerations stay identical (see test_strategy).
(3) SCHEDULER + CROSS-THREAD IN-FLIGHT. Under `Pool.mutex` (scheduler.zig:64) mark every queued `Task.block` and `Task.seed` handles in queue_default/queue_io (scheduler.zig:43,67); `DriverWakeup.mailbox_entries[].value` under the mailbox lock (coroutines.zig:56,90); kotlinx ChannelState buffer/send_waiters/receive_waiters (kotlinx_coroutines.zig); `RuntimeError.Thrown`/`.Return` Values pending in `Vm.threads` (ThreadTable). The in-flight `Task` between `takeEligible` (scheduler.zig:289) and entering `runVmTask` is pinned on the worker's scratch-root vector (set `in_pool_task` worker pushes task.block before run, pops after).
(4) GLOBALS/PROGRAM GRAPH. Register every live `Vm` (the driver + each worker's materialized child Vm) in a `VmRegistry`; dedup by cell identity via the mark epoch. Mark globals(`ObjRef(Env)` vmhost.zig:219), classes(`ObjRef(ClassTable)` → ClassDef graph), object_states, prog top-level prop inits, out_sink, anon_methods, closures (vmhost.zig:219-230). With PERM GEN most of these are implicitly live (perm cells are not scanned), so this set is primarily the mutable globals Env + object_states.
(5) HOST-OP TEMPORARIES — the one non-structural case. Closed by the DEFERRAL RULE (no collection mid-host-op) + a threadlocal scratch-root vector. A host op that builds Values not yet stored into any frame register pushes them onto its thread's scratch-root vector; since collection only fires at the opcode boundary AFTER the host op returns and `frame.write` (eval.zig:576) stores the result, in practice the deferral rule alone covers almost all of it. The scratch vector is the safety net for host ops that themselves reach a nested safe point (a host op that re-enters `evalWithCapturesChained` to call a Kotlin lambda — e.g. `map`/`forEach`/comparator); those nested frames are roots by (1), and any Value the outer host op holds across the re-entry goes on the scratch vector.

MARK & SWEEP. MARK: tri-color worklist as an explicit `std.ArrayList(*GcHeader)` grey stack (NOT native recursion — graphs are deep/cyclic and the evaluator already caps native recursion at ~2000). Seed grey from roots (1)-(5); on pop, black-mark (mark_epoch = current) and push white children via `trace_fn`. Cycles terminate: a black cell is never re-pushed (the cycle-collection win refcounting structurally lacks). The collector reads payloads lock-free because the world is stopped (stop-the-world IS the synchronization). SWEEP: walk each generation's intrusive list; white (mark_epoch != current) cells are unlinked, `finalize_fn`'d, freed. CRITICAL: the finalizer is the SHALLOW free — split each payload `T.deinit` into `deinitShallow` (free only the cell's OWN buffer: the ArrayList spine, the dup'd StringRef bytes, the Env HashMap spine, RegexData.engine, StringBuilder/DriverWakeup ArrayLists) and leave child Value cells to be swept independently. This deletes the recursive release walks `releaseValueList`/`releaseSliceElems`/the Map arm (value.zig:580-597) and makes each cell freed EXACTLY ONCE regardless of sharing — eliminating the double-free class (the ~19 audited UAFs) structurally. No Kotlin finalizers exist, so finalization order is irrelevant.

SAFE POINTS & CONCURRENCY. The ONLY safe point is the top of the `runFrameInner` block loop (eval.zig:891/896, beside the existing `shouldAbandon()` poll) and the equivalent in `resumeContinuation`'s frame loop. The poll is a relaxed atomic load of `gc_requested` — the same near-zero cost as the proven `shouldAbandon()` cadence. DEFERRAL: `ObjRef.initOwned`/container-growth only bump a `bytes_since_gc` counter and, on crossing the threshold, set `gc_requested`; they NEVER collect inline, so a host op building 10k cells simply arms the request and collection fires at the next boundary after the op returns and `frame.write` stores its result. MULTI-THREAD STW: reuse the `requestAbandon`/`shouldAbandon` rendezvous machinery (threads.zig:79-113) as the template. Add `gc_stop_requested` + per-thread `at_safepoint` ack + a barrier. The thread that observes `gc_requested` CAS-wins to become the sole collector; every other interpreter/worker thread parks at its next boundary (and at the scheduler idle poll scheduler.zig:294 and pump loops in coroutines.zig), acks, spins until released. A thread blocked OUTSIDE the evaluator (real Thread.sleep/clockSleepMillis at clock.zig:59/mailbox wait/join) is SAFE BY CONSTRUCTION: it unwound to the pump, holds no un-rooted Value on its native stack, its live Values are in parked snapshots/scheduler queues (roots 2-4). Bracket the blocking primitives with `enterSafepoint`/`exitSafepoint` (set `at_safepoint` before blocking; on wake spin on gc phase BEFORE touching any Value) and an `in_evaluator` flag so the collector treats a blocked thread as already-parked. Mark/sweep takes only READER locks on cells in a writer-quiescent world, so no collector↔worker deadlock; lock ordering is safe because threads stop at boundaries holding NO cell/registry lock (host critical sections are bounded and exit before the boundary). Rendezvous is bounded (pool ceiling max(64,nproc), ms poll cadence).

TRIGGER & PERF. Allocation-bytes threshold: `bytes_since_gc` crosses a dynamic high-water mark = max(min_heap, live_after_last_gc * growth_factor 1.5-2.0) — Appel sizing, so the heap grows geometrically and RSS plateaus at ~growth_factor × working set (the property arena mode lacks). KLIO_GC_* env knobs mirror KLIO_RECLAIM (objcell.zig:107-136 reuse the cached env-state pattern); KLIO_GC_STRESS=1 collects at EVERY safe point (correctness oracle). PERMANENT GEN: cells minted during stdlib decode / module load (the immutable ClassDef/module image, ~127MB) go to a non-collected perm region (repurpose the process-lifetime arena, main.zig:30) marked implicitly-live WITHOUT scanning, so mark cost ∝ runtime live set, not the immutable graph. A perm cell is recognized by `gen == perm` and is never swept and never pushed to the grey stack (its children are also perm/implicitly-live). The `gc_alloc_gen` threadlocal is flipped to nursery once the program body starts executing.

STAGED PATH. Stage 1 (correctness): non-generational STW mark-sweep over the intrusive list, perm-gen for stdlib, refcount neutralized, KLIO_GC_STRESS + KLIO_GC_VERIFY oracles, validated against the full corpus + ktor server with ZERO per-site ownership work. Stage 2 (sweep/alloc cost): per-size-class free-list allocator over its own pages + per-thread free-lists so sweep is O(live) and allocation skips the global lock. Stage 3 (throughput): non-moving generational nursery (promote-in-place = gen-bit flip + list move, NOT a copy, preserving address identity); minor GC scans roots + remembered set; a write barrier ONLY at heap-mutation sites — InstanceData.set/define (class.zig:290/306), Env.define (env.zig:32), container appends in host ops, frame.write/CellSet (eval.zig:576/1306). Registers/frames/snapshots are always fully scanned as roots, so they need NO barrier. Stage 4 (latency): incremental/tri-color marking with a Dijkstra/Yuasa barrier (the same write barrier) to bound STW to root-scan only for large old heaps; lazy/background sweep.

ADVERSARIAL HOLES RESOLVED (the prompt left the list empty; these are the real ones found by reading the code):
- HOLE A (StringRef dupe ambiguity): `ObjRef.init` (objcell.zig:313-318) dupes `[]const u8` only under reclaim. Under GC, bytes MUST always live in the GC heap (the cell owns and shallow-frees them at sweep), so the dupe is UNCONDITIONAL in GC mode for `init`, while `initOwned` adopts the caller buffer verbatim. Any caller that previously passed a borrowed module-const slice through `init` is fine (dupe makes it owned); any caller passing borrowed bytes through `initOwned` (expecting no free) must be audited — fix: such call sites either dupe first or the bytes are perm-region bytes (which are never swept). Resolved by: in GC mode, perm-gen StringRef cells whose bytes point into the module arena set a `borrowed_bytes` flag in the header so `deinitShallow` skips the free.
- HOLE B (cross-thread Value in a register of a RUNNING-on-another-core worker during STW): the collector only proceeds once ALL threads have acked at a safe point, so no thread is mid-opcode with an un-rooted Value when marking reads its frames. The barrier is the synchronization. A thread that cannot reach a safe point because it is blocked in a real syscall is handled by enterSafepoint/exitSafepoint (it pre-acks).
- HOLE C (host op re-entering the evaluator holding a Value not on any stack): the nested `evalWithCapturesChained` is itself a safe-point-bearing region; the outer host op's live Values go on the threadlocal scratch-root vector (root 5) for the duration of the re-entry. Audit target: every host op in host_call_*.zig that loops calling a Kotlin lambda (map/filter/sortedBy/comparator/fold).
- HOLE D (RuntimeError carrying a Value across the unwind, e.g. `.Throw`/`.NonLocalReturn`/`.Return`): these Values are local to the native stack between frames during unwind. They are roots via the frame node's `try_stack`/pending fields and the scratch vector; the collector cannot run mid-unwind because there is no safe point between `execInst` returning `.err` and the catch handler — the next safe point is the top of the loop, by which time the Value is either stored or on the scratch vector.
- HOLE E (ClassDef graph as a leak / mis-collection): resolved by perm-gen — the class image and module are minted into perm and never swept; instances reference their class via a normal trace edge but the class itself is implicitly live.
- HOLE F (DebugAllocator under GC): keep `AllocChoice.debug` working under GC so leak/UAF verification reports clean by construction; a missed root surfaces as a poison-on-free read (sentinel written over freed cells) + the KLIO_GC_VERIFY conservative-scan assertion.

REFCOUNT MIGRATION (staged, build stays green). Phase A NEUTRALIZE: `Value.retain` (value.zig:452) / `Value.release` (value.zig:513) become no-ops in GC mode; they already short-circuit on `!reclaimEnabled()` (value.zig:457), so GC mode reuses the proven no-op path. `ObjRef.deinit` (objcell.zig:355) becomes no-op-free in GC mode (keep the `if (!reclaim_tls) return` early-out); a missing retain is now harmless and an extra release is harmless. `ObjRef.clone` keeps the atomic add (backs strongCount/identity). Phase B REPLACE deinit semantics: split each `T.deinit` into `deinitShallow` for the finalizer; delete the recursive child-release loops and the `strongCount` reads that gate them (value.zig:534/581). Phase C ALLOCATOR: add `AllocChoice.gc` to objcell.zig:130/main.zig:28 installing the GcHeap (a real freeing page/free-list allocator); repurpose the process-lifetime arena (main.zig:30) as the perm gen; keep DebugAllocator under GC for verification. `reclaimEnabled()`/`setReclaim` repurposed to `gcEnabled()`/`setGc` with identical spawn-seed inheritance. Migration ordering: first run the GC tracer ALONGSIDE refcounting on a debug build asserting mark-set == refcount-reachable-set (parity check); then flip deinit to no-op-free and let GC own frees; then delete dead retain/release sites incrementally.

ORACLES: KLIO_GC_VERIFY runs the collector AND a conservative native-stack/register scan, asserting every conservatively-reachable cell is precisely-marked — a missed root becomes a deterministic assertion, not a production UAF. KLIO_GC_STRESS collects at every safe point. Poison-on-free debug mode writes a sentinel over freed cells so any UAF from a missed root names itself, paired with the DebugAllocator quarantine (main.zig:39-40).

## Test strategy

Layered, each layer must FAIL if the corresponding mechanism regresses.

1. Module unit tests (zig build test): keep every existing objcell.zig (lines 511-786 incl the cross-thread push/counter/handoff stress), class.zig, env.zig, value.zig test green unchanged through Stage 0 (proves the GcHeader + forEachChildCell refactor is behavior-preserving). Add new gc.zig tests: (a) mark a hand-built cyclic Value graph (two InstanceData fields pointing at each other) from a synthetic root set and assert both survive, then drop the root and assert both are swept — directly proving cycle collection, the property refcounting lacks; (b) a shared cell reachable from two roots is freed exactly once (no double-free) when both roots drop — proving the ~19-UAF class is eliminated structurally; (c) deinitShallow frees only the cell's own buffer and never recurses into child cells.

2. Root-completeness oracles (the hardest correctness property): KLIO_GC_VERIFY runs the precise collector AND a conservative native-stack/register scan and asserts precise-marked ⊇ conservatively-reachable — a missed root is a deterministic assertion, not a production UAF. KLIO_GC_STRESS=1 collects at EVERY safe point so any root gap manifests on the very next opcode. Poison-on-free writes a sentinel over freed cells so a UAF from a missed root names itself. A dedicated unit test asserts SuspendState.markRoots / FrameSnapshot.markRoots enumerate the SAME set as retainSnapshotValues (eval.zig:405) — the migration's load-bearing invariant (root set == proven-necessary retain set).

3. End-to-end corpus (build.zig:40 examples runner + tests/corpus/expected): run the ENTIRE corpus under KLIO_RECLAIM=gc with KLIO_GC_STRESS=1 and assert byte-identical output to the baked expected output. This is the regression net: every language feature (string templates, smart casts, lambdas, when-exhaustiveness, coroutines, sequences, maps) is exercised through the real lexer→parser→resolver→interpreter pipeline with the collector hammering every safe point. A missed root or premature free corrupts output and fails the diff.

4. Concurrency + coroutine itests under gc mode: ktor_client_get, ktor_channel_async, ktor_server, concurrency_stress, plus the coroutine_smoke/threaded_litmus fixtures (build.zig:122-157, tests/fixtures). Run with KLIO_RACE_JITTER to widen cross-thread windows. These exercise parked coroutines (roots 2), scheduler queues + cross-thread in-flight Values (roots 3), real worker threads + STW rendezvous, and channel buffers — the root sources structural analysis is most likely to miss.

5. The decisive memory gate: ktor_server (the program that DEFEATED refcounting) served every route under sustained load with FLAT RSS — assert the Appel high-water plateau via scripts/klio-guard.sh RSS sampling, demonstrating bounded RSS for a long-running server with ZERO per-site ownership work. Compare against the same run under KLIO_RECLAIM=smp (refcounting) to confirm the cycle/leak that grew RSS under refcounting is now collected.

6. Migration parity gate: a debug build runs the GC tracer ALONGSIDE live refcounting and asserts mark-set == refcount-reachable-set on every collection before deinit is flipped to no-op-free — catching any tracer/retain divergence before it can cause a free.

7. DebugAllocator under gc (AllocChoice.debug + gc): the whole corpus + itests must report zero leaks and zero UAF by construction.


## Residual risks

1. Root-completeness is a proof obligation, not a theorem: any NEW host op or interpreter path that holds a Value off-stack across a safe point without pushing it to the scratch-root vector (root 5) reintroduces a UAF. Mitigation: KLIO_GC_VERIFY conservative-scan + poison-on-free + KLIO_GC_STRESS catch it deterministically in test, and the deferral rule (no collection mid-host-op) makes the window exist only for host ops that re-enter the evaluator (map/filter/fold/comparator) — a small, auditable set. The risk is permanent vigilance, not a one-time fix; a lint/assert that any host op calling evalWithCapturesChained must first arm scratch roots would harden it further.

2. STW pause until Stage 4: Stages 1-3 stop the world for the full mark (Stage 1) or full-old mark (Stage 3). For a server with a very large old working set this is a user-visible pause. Mitigation: perm-gen excludes the ~127MB immutable image from scanning (mark cost ∝ live runtime set), and Stage 4 makes marking incremental. Until Stage 4 ships, worst-case pause scales with live old-gen size.

3. StringRef byte-ownership audit (HOLE A): every initOwned caller passing borrowed (non-perm) bytes must be found and fixed (dupe or perm-mark), or deinitShallow frees borrowed module-const bytes. The borrowed_bytes header flag handles perm bytes, but a non-perm borrowed-bytes caller is a latent corruption. Mitigation: grep all `StringRef.initOwned`/`ObjRef([]const u8).initOwned` sites during Stage 1; DebugAllocator + poison-on-free surface a stale free.

4. Cross-thread mark under SpinRwLock assumes host critical sections are bounded and always exit before the next safe point. A host op that takes a cell writer-lock and then reaches a safe point WITHOUT releasing it would deadlock the collector (which takes reader locks). Mitigation: the invariant ("threads stop at boundaries holding no cell lock") must be verified for every borrowMut span; the evaluator/stdlib already copy out of borrows before running user code (objcell.zig:16-21 documents this), so the existing discipline carries over, but it is an invariant to keep, not a guarantee.

5. enterSafepoint/exitSafepoint bracketing of every blocking primitive (clockSleepMillis @clock:59, mailbox wait, Thread.join) must be exhaustive — a blocking call NOT bracketed would stall the STW rendezvous (the collector waits forever for an un-acked thread). Mitigation: enumerate every blocking syscall site; a watchdog timeout on the rendezvous that dumps which thread failed to ack would make a missed bracket a loud failure rather than a hang.

6. Performance of Stage 1 (per-cell destroy sweep, global alloc lock) is acceptable for correctness validation but not production throughput; Stages 2-4 are required for production-grade efficiency, so the GOAL's 'production-grade' bar is only fully met after Stage 4. Stage 1 alone meets the correctness bar (general correctness, cycle collection, bounded RSS) but trades pause time and alloc throughput.
